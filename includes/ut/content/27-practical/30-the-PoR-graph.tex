\subsection{The PoR Graph}

As a simplex ages, a complex graph of PoRs is produced (and it is a DAG).
Each vertex represents a block in some simplex-chain, and the outgoing edges point to reflected blocks.
An example section of a simulated PoR graph is shown in \autoref{fig:por-graph-example}.

Since there are $N_1$ chains, and each block has $\sim N_1$ reflections on average, the total number of reflections, per block period, is $\sim {N_1}^2 = O(c^2)$.
Does this present a problem for fully validating nodes that wish to verify the entire PoR graph?

Recall that in \autoref{sec:exploiting-segmented-state}, we took advantage of redundant data within the PoR graph.
Particularly that, provided we knew \emph{which} blocks were reflected and the \emph{ordering} used to create the PoRs root, we could deterministically reconstruct those parts of any simplex-chain block.
However, this relied on either tracking \emph{the entire} PoR graph, or additionally downloading all missing merkle branches corresponding to PoRs used by the reflected block.

Why is so much information required?
The reason is that each miner can choose \emph{whether} to reflect any remote block (assuming that the block is available), and has freedom to choose the \emph{position} of each reflected block in the merkle tree of PoRs.

Regarding the \emph{position} of reflected blocks --- this is easy to solve.
All we need to do is ensure there is only one position that a block can be in.
For example, we could require that reflected blocks are ordered based on the ordering of their genesis blocks (which is fixed).
If two or more blocks from a single simplex-chain are reflected, we can use a sub-ordering method (of which there are many options).
This gives us a total ordering, meaning that we only need to know \emph{which} blocks were reflected to reconstruct this segment of a block.
Alternatively, we could use a merklized prefix tree which achieves the same goal.
Either way, we have reduced the required information from a \emph{list} of block hashes to a \emph{set} of them.

It is clear that miners need some freedom to choose \emph{whether} to reflect a block or not.
For one, miners must be able to choose to reflect \emph{new} blocks as they appear.
Additionally, due to the \AxiomOfAvailability, miners must not reflect unavailable blocks, even if a valid PoR can be generated.
However, because all honest miners obey the \AxiomOfAvailability, there is never a reason for an honest miner \emph{not} to reflect a block that is available --- doing so will always increase the overall chain-weight of that miner's draft block.

So, if an honest miner's block, \BL{}, reflects some block, \BR{}, then any block reflected by \BR{} must also be available (since the \AxiomOfAvailability is recursive).
If a block is available then a PoR is possible.
Therefore, an honest miner should reflect all non-local blocks that were reflected by \BR{} but have not already been reflected by an ancestor of \BL{}.

Let's call this a state of \emph{maximal reflection}, and say that such a PoR graph is \emph{maximally reflective}.

\subsubsection{Maximally Reflective PoR Graphs}

\label{sec:por-graph-max-refl}

Specifically, we can say this about any PoR graph in a state of maximal reflection: for every block \BL{}, and for every block \BR{} reflected by \BL{}, then every block $b$ that is reflected by \BR{} satisfies one of: $b$ is reflected by \BL{}; or $b$ was reflected by an ancestor of \BL{}; or $b$ is an ancestor of \BL{}.

Notice that, if \BL reflected any blocks, there will always be at least one block that \emph{was} reflected by \BL that was \emph{not} reflected by any other block that was reflected by \BL.
Let us call these blocks the \emph{tips} of the PoR graph from \BL{}'s perspective.
PoR graph tips might reflect other blocks reflected by \BL, too.

For example, consider this PoR graph segment between 3 chains \cL, \cQ, and \cR:
\begin{equation*}
    \xyMChains{
        \xyL{\text{Chain \cQ}} & \cdots & & & \xBQ{} \arm[lll] \arf[lld] \arf[ldd] & \\
        \xyL{\text{Chain \cL}} & \cdots & \xBL{-1} \arm[l] & & & \xBL{} \arm[lll] \arf[lld] \arf[lu] \\
        \xyL{\text{Chain \cR}} & \cdots & & \xBR{} \arf[lu] \arm[ll] & & \\
        \xyTimeHoriz{rrrrr} &&&&&
    }
\end{equation*}
Here, \BL{} reflects both \BQ{} and \BR{}, and \BQ{} also reflects \BR{}.
Thus, from \BL{}'s perspective, \BQ{} is a \emph{graph tip}; and, from \BQ{}'s perspective, \BR{} is a \emph{graph tip}.

Starting from \BL{-1}, we could completely describe this section like so:
\begin{itemize}[notopsep, noitemsep]
    \item \BR{} reflects \BL{-1}; and
    \item \BQ{} reflects \{{\BR{}, \BL{-1}}\}; and
    \item \BL{} reflects \{{\BQ{}, \BR{}}\}.
\end{itemize}

If the PoR graph is not maximally reflective, then we must specify the complete set of reflections for each block.
However, \emph{when maximally reflective}, most of that information is redundant (about half in this example).

We \emph{do} still need some information for each block, however, we can recreate the full PoR segment with less information --- some of the reflections are \emph{implied} and can be omitted:
\begin{itemize}[notopsep, noitemsep]
    \item the PoR graph segment is maximally reflective; and
    \item \BR{} reflects the tip \BL{-1}; and
    \item \BQ{} reflects the tip \BR{}; and
    \item \BL{} reflects the tip \BQ{}.
\end{itemize}

We can see that the maximally reflective quality has at least two important properties.
Firstly: we have \emph{drastically}\footnote{
    The theoretical overhead is still $O(c)$ per block, but practically we expect the overhead to be a similar size to the header which is $O(1)$.
    It's explained shortly.
} reduced the amount of information needed to completely describe the graph segment: $O(c^2) \to \sim O(c)$ --- an example is shown in \autoref{fig:por-graph-tips}.
Secondly: the PoR graph, according to each chain, \emph{converges} into a single, consistent PoR graph.
In essence, any block in a maximally reflective PoR graph shares a \emph{common history} with all prior blocks in the graph.

\begin{figure}
    \centering
    \includegraphics[]{27-practical-30-fig3-por-graph-tips_sag.pdf}
    \caption[Maximally reflective PoR graph segments can be described using $\sim O(c)$ information.]{
        This demonstrates how maximally reflective PoR graph segments with $O(c)$ many chains can be described using $\sim O(c)$ information.
        Thick dotted arrows represent reflections of PoR graph \emph{tips}, and semitransparent arrows show other reflections --- these reflections and implied via the reflection of the graph tips.
        This also shows that the DAG of tip-reflections is the \emph{longest} path of reflections between two blocks.
    }
    \label{fig:por-graph-tips}
\end{figure}

Is there an intuitive explanation for the reduction in complexity of the PoR graph?
Yes.
To start with, let us assume that there is no \emph{propagation delay} --- i.e., all miners instantly receive, validate, and incorporate all blocks into the PoR graphs of their draft blocks.
In this case, no blocks are ever mined simultaneously, and so each block will reflect exactly one PoR graph tip.
Since there are $O(c)$ many chains, and we need to add $O(1)$ extra information per header (the reflected tip), this is $O(c)$ extra information all up.

In practice, blocks \emph{will} sometimes be mined simultaneously.
So, even if \emph{most} of the time a block only reflects one tip, \emph{some} of the time that block will reflect multiple tips.
The frequency of simultaneous blocks is dependent on the number of chains ($N_1$), the block frequency of each chain ($B_f$), and some average propagation delay ($\phi$ seconds).
Two blocks are simultaneous if they are mined within $\sim \phi$ seconds of each other.
In the $\phi$ seconds before that most recent tip was mined, we expect that $\sim N_1 B_f \phi$ other tips were mined (from any simplex-chain).
\pz{Where does $1 - {N_1}^{-1}$ come from?}
Unless a block contains no reflections (which happens with probability $1 - {N_1}^{-1}$), it must reflect at least one graph tip.
So, we expect each block to reflect $1 + N_1 B_f \phi$ tips.
For $N_1 = 100, B_f = \nicefrac{1}{15}, \phi = 1$, we expect
each block to be simultaneous with $\sim 7$ others, and each block to reflect 8 graph tips on average.

\pz{0.3 seconds propagation delay is not realistic for a network.}
Therefore, the overhead to reconstruct the PoR graph --- and every PoR segment of every simplex-chain block --- is, on average, $g (1 + N_1 B_f \phi)$ bytes per block, where $g$ is the length of a hash.
As $g$, $1$, and $B_f$ are constants, and if we treat $\phi$ as constant, the overhead thus has complexity $O(c)$ \emph{per simplex-chain}.
Since we're tracking $O(c)$ chains, the overall load is $O(c^2)$.

The total bandwidth required to track the PoR graph (excluding verifying the availability of blocks) is: the overhead per block, plus the block header, all multiplied by the network-wide blocks per second rate.
Thus, the total bandwidth is $N_1 B_f (B_h + g(1 + N_1 B_f \phi))$ B/s --- which is $O(c^2)$.

However, we estimated before that we should expect to require 7 graph tips on average per block (which seems much less than $O(c)$).
Practically speaking, the overhead is only significant when the header size is much smaller than the overhead: $B_h \ll g (1 + N_1 B_f \phi)$.
If we plug in our rough numbers from before, we find $g (1 + N_1 B_f \phi) \approx 250 \approx 2 B_h = O(1)$.

There \emph{is} a practical limit (depending on $B_f \phi$) for how large $N_1$ can grow before this overhead is non-negligible.
\emph{However}, if we capped the expected overhead to, say, 256 bytes --- $g (1 + N_1 B_f \phi) \le 256$ --- then we find $N_1 \le 7(B_f \phi)^{-1} \approx 105 \cdot \phi^{-1}$.
Capping the overhead to 128 bytes yields $N_1 \lesssim 45 \cdot \phi^{-1}$.
Note that maximal values of $N_1$ are inversely proportional to $B_f$, so modifying $B_f$ doesn't change the expected overhead.

\subsubsection{Optimization or Contradiction?}

We calculated the overhead to be $g(1+N_1 B_f \phi) = O(c)$ --- this is because we assumed that $O(B_f \phi) = O(1)$.
However, if this were really the case, we should be able to optimize the PoR sections of blocks (similar to \autoref{sec:exploiting-segmented-state}).

We could try to design the protocol like this: \emph{instead of recording all reflections, each block records only the minimum necessary to reconstruct the PoR graph}.
This would increase the overall bandwidth required to track the PoR graph, but our expression remains the same: $N_1 B_f (B_h + g(1 + N_1 B_f \phi))$.

Since the overhead is $O(c)$, and recording all reflections is also $O(c)$, can we swap in this new process to increase scalability?

The old PoR sub-block takes up $N_1 B_f \alpha$ B/s of capacity (where $\alpha$ represents the bytes per reflected simplex-chain and $\alpha \in [16, 512]$).

The new PoR sub-block instead takes up $B_f \cdot g(1 + N_1 B_f \phi)$ B/s of capacity --- we exclude the block's header since that's already part of the block.
If $k_{1,B}$ B/s of a chain's capacity is dedicated to reflections, then we have:

    \label{eq:bad-n1-with-phi}
\end{align}

Since this conflicts with our notion of an $O(c)$ load, let's examine one of our premises: that $O(N_1 B_f \phi) = O(c)$.
Certainly $O(N_1) = O(c)$, and $O(B_f) = O(1)$, but does $O(\phi) = O(1)$?

There is a good reason to think $O(\phi) = O(1)$.
At some point, propagation delay is limited by the speed of light.
So latency must have a definite minimum, which is a constant.

\pz{The graph cannot be fully connected and we use gossip so shouldn't $\phi$ have a term in $\log(n)$?}
However, the physical limits on latency do not dominate real-world latency yet.
Near-future networking technologies, like LEO satellite constellations, will reduce latencies over significant distances.
Moreover, even as the best-case minimum latency approaches physical limits, technology will continue to improve latency in \emph{bandwidth intensive} contexts.\footnote{
    This is something we didn't consider when estimating $N_1$ in \autoref{eq:bad-n1-with-phi} --- that the propagation delay will increase as the excess capacity of nodes' available bandwidth decreases.
    Like all such systems, response time is inversely proportional to excess capacity.
}
Therefore, $O(\phi)$ \emph{should not} be considered $O(1)$, but rather should be considered $O(c^{-1})$: as technology improves, $\phi$ decreases.

If $O(\phi) = O(c^{-1})$, this resolves the contradiction.
% First, recall $N_1 \propto \phi^{-1}$ from \autoref{eq:bad-n1-with-phi}.
% This is a contradiction if $\phi$ is $O(1)$, but makes sense if $\phi$ is $O(c^{-1})$.
It means that $O(N_1 B_f \phi) = O(1)$.
That matches our intuition from earlier, \emph{and} means that maximally reflective PoR graphs really are only $O(c)$ complex, rather than $O(c^2)$.

We can also explain why we had such a large $N_1$ estimate before --- we took an $O(1)$ load and blew it up to an $O(c)$ load.
So we effectively changed $O(N_1)$ from $O(c) \to O(c^2)$.
That meant that network-wide bandwidth and storage requirements went from $O(c^2) \to O(c^3)$.

There is also an argument that $\phi$ depends on the number of nodes in the P2P network --- that would take the form of a $\log_b(n)$ term in $O(\phi)$.
While this is true for naive gossip protocols, in practice we see that miners will go to some effort to specifically reduce latency for block propagation.
Under near-ideal conditions, miners can propagate new blocks and reflections to one another with near-zero local overhead (compared to the milliseconds of latency between them).
Since this propagation is constrained by the latency between these special nodes, and not by the size of the network as a whole, we will ignore any $\log_b(n)$ component of $\phi$.

\subsubsection{\AxiomOfRawMaximalReflection}

It should be clear that there are decisive advantages for \UT{} if the PoR graph is maximally reflective.
Particularly, we can accurately describe the PoR graph entirely via \emph{new reflections}, greatly reducing PoR overhead.
Thus, we will require it via a protocol rule: the \AxiomOfMaximalReflection.

\DeclareAxiom{MaximalReflection}{%
    A miner should reflect all possible blocks.
}{%
    A block, \BL{}, is invalid unless, for each reflected block \BR{}:
    \begin{axiomreqs}
        \item \BR{} is valid under this Axiom; and
        \item each block that was reflected by \BR{} or is a parent of \BR{}:
        \begin{enumerate}[label=\alph*.]
            \item is reflected by \BL{}; or
            \item is an ancestor of \BL{}; or
            \item was reflected by an ancestor of \BL{}.
        \end{enumerate}
    \end{axiomreqs}
}

It is worth noting that this axiom does not impact honest miners --- it is in their interest to produce maximally reflective PoR graphs.
However, this \emph{does} impact dishonest miners since reflecting other chains becomes all-or-nothing.

If a dishonest miner is determined to selectively reflect only \emph{some} simplex-chains, their valid blocks cannot reflect any other blocks that are less selective.
Honest miners, on the other hand, \emph{can} reflect the dishonest miner's blocks.
Thus, the \AxiomOfMaximalReflection creates an asymmetry between honest and dishonest miners.

\subsubsection{The Longest PoR Chain}

\autoref{fig:por-graph-tips} shows us an interesting feature of maximally reflective PoR graphs: between two given blocks, the union of the paths via PoR graph tips both \emph{visit every block} and are the \emph{longest} paths between any two blocks.
This is somewhat self-evident: since the PoR graph is a DAG, there is no way to return to a block once we have visited it.
Thus, if a path exists that visits every block, then it must be a longest path because there are no unvisited blocks.
A longer path would need to visit more blocks, but there are no more blocks, therefore no longer path exists.

Although it makes sense to refer to these paths as the \emph{longest} --- this isn't always strictly true.
First, we should notice that multiple paths are possible, and are expected to occur when blocks are created near-simultaneously.
In some cases, these paths can be different lengths.
For example:
\begin{equation*}
    \xyMChains{
        \xyL{\text{Chain \cQ}} & \cdots & & \xBQ{-1} \arm[ll] \arf[ld] & \xBQ{} \arm[l] & \\
        \xyL{\text{Chain \cL}} & \cdots & \xBL{-1} \arm[l] & & & \xBL{} \arm[lll] \arf[lld] \arf[lu] \arf[llu] \\
        \xyL{\text{Chain \cR}} & \cdots & & \xBR{} \arf[lu] \arm[ll] & & \\
        \xyTimeHoriz{rrrrr} &&&&&
    }
\end{equation*}
Here, we can see that \BL{} reflects the tips \{{\BQ{}, \BR{}}\}.
There are two paths from \BL{} to \BL{-1} in this case: one via $\BQ{}\to\BQ{-1}$, and the other via \BR{}.
Both are a longest path in the sense that they are locally maximal: no paths including \BR{} (or \BQ{}) are part of a longer path to \BL{-1}.

So, really, what we have identified is the DAG of the union of the longest paths between two blocks.
This is exactly the information that is necessary to reconstruct a maximally reflective PoR graph.

Let's refer to this as the \emph{longest PoR chain}, even though it is technically a DAG.
Of all possible PoR DAGs that both include all edges leading to a graph tip and visit every block, the \emph{longest PoR chain} has the fewest edges, and is thus the most chain-like of those DAGs.
Additionally, in \autoref{sec:dags-and-the-por-graph} we will discuss some symmetries between blockchains and the longest PoR chain.

    On the other hand\dots{} well the other hand is a problem that we can't solve, yet --- we'll ignore it for now and return to it in \autoref{sec:dags-and-the-por-graph}.
}

    Subsequent sections regarding NIPoPoWs will, likewise, be speculative.
    \UT{} won't depend on NIPoPoWs, but they are useful and it would be good to support them, if possible.

\subsubsubsection{NIPoPoWs Primer}

Prior work: \citeNIPoPoWsFull{}.

\bquote{
    Non-Interactive Proofs of Proof-of-Work (NIPoPoWs) are short stand-alone strings that a computer program can inspect to verify that an event happened on a proof-of-work-based blockchain without connecting to the blockchain network and without downloading all block headers. For example, these proofs can illustrate that a cryptocurrency payment was made.
}[\href{https://web.archive.org/web/20210520174729/https://nipopows.com/}{What are NIPoPoWs? (nipopows.com)}]

NIPoPoWs are possible due to the statistical properties of proofs of work.
They require an additional interlink structure between blocks.
The interlink structure is a kind of skip-list, where a block at height $h$ links back to $\sim \log_2 h$ other blocks.

The insight that enables NIPoPoWs (and PoPoWs more generally) is that some PoWs will be \emph{much} lower than the difficulty target, and that the frequency of these special PoWs is dependent on the total number of PoWs that have been produced.
That is: if the PoW target is $2^{184}$, then all valid PoWs will be $\le 2^{184}$, 50\% will be $\le 2^{183}$, 25\% will be $\le 2^{182}$, and so on.
We can generalize this via the statement: $P(\text{PoW} \le 2^{184 - \mu}) = 2^{-\mu}$ --- the probability that the proof of work is less than or equal to $2^{184-\mu}$ equals $1/2^\mu$.
In essence, $\mu$ is a measure of the \emph{excess capacity} of a block's PoW: how many orders-of-magnitude lower \emph{could} the target have been, given the \emph{actual} PoW.

When a block has $\mu > 0$, it is a $\mu$-superblock, and it is these superblocks that the interlink structure uses.
Particularly, for each integer value of $\mu$, each block links back to the most recent $\mu$-superblock.
The chain of $\mu$ level blocks is the $\mu$-superchain.
Note that the 0-superchain (or 0-chain) is identical to the blockchain itself.
This interlink structure is partially shown in \autoref{fig:nipopows}, which shows each $\mu$-superchain according to the perspective of the right-most block.
The full interlink structure is shown in \autoref{fig:nipopows-interlinks}.

Intuitively, a NIPoPoW works because it uses the (very short) top-most chain of $\mu$-superblocks as a basis to hone in on a target block (denoted $\mathcal{C}[-k]$ in the NIPoPoW paper) a few confirmations behind the chain tip.
This is done by progressively inspecting the most recent segments of lesser and lesser $\mu$-superchains to establish the expected chain-weight that has been contributed to that target block.\footnote{
    The NIPoPoW algorithms don't do this exactly, but they embody similar and convergent knowledge.
}
This is the main \emph{suffix proof}, as it proves the blocks at the recent end (suffix) of the blockchain.
(Additionally, the most recent $k$ blocks ($\mathcal{C}[-k:]$) are included alongside the proof.)
The work required to generate the main suffix proof is (approximately) as much work as has been contributed to the entire blockchain history.
Thus, an adversarial NIPoPoW requires (approximately) as much work as the total chain-weight of the honest chain, so NIPoPoWs are secure.\footnote{
    This is a simplification --- see \citeNIPoPoWs for full details.
}

Now that the chain-head and relevant $\mu$-superchains have been proven, arbitrary blocks in the chain's history can be proven.
This is done by `following down' from a top-level $\mu$-superblock to the target block, following the interlink structure.
Starting with the \emph{earliest} $\mu$-superblock between the target block and $\mathcal{C}[-k]$, up to $\mu$ levels are progressively descended until the target block is reached.
`Following down' means: for a $\mu$-superblock, check if the previous block at level $(\mu-1)$ occurred \emph{after} the target block --- if so, that block becomes the next in the series, otherwise decrease $\mu$ by one and repeat with the current block.
The proof terminates at the target block.
The blocks that are traversed comprise the \emph{infix proof} for that block.

An example of a NIPoPoW with a suffix and infix proof is shown in \autoref{fig:nipopow-proof}.

Notice that there is no concept of \emph{state} used when reasoning about NIPoPoWs --- we're only considering a chain of interlinked blocks with PoWs.
Put another way: there is no requirement that these blocks belong to the same blockchain; only the PoW and interlink structure matters.

So, at first glance, it appears that the longest PoR chain might work with NIPoPoWs, or some modified variant, at least.

There are two important caveats that are mentioned in the NIPoPoW paper; these are problems for us and we will have to address them.

First: the authors assume a single chain of blocks, not a graph.
Thus, \emph{any} simultaneous blocks in the PoR graph are an issue.

Second: the authors assume a constant difficulty.
For a traditional blockchain, this isn't too much of a problem.
For \UT{}, however, we ideally want uncoupled simplex-chain difficulties, even if they use the same hashing algorithm.
Speaking of which, how does a NIPoPoW work if more than one hashing algorithm is used?

\subsubsubsection{Non-Interactive Proofs of Proof of Work Reflection (NIPoPoWRs)}

\label{sec:nipopowrs}

Before we discuss the problems mentioned above, it is important to note that the method we will devise cannot make use of converted work from non-PoW blocks (e.g., if some simplex-chain used PoS, or PoA, etc).
That's because there is no real sense to such a block being `lucky' in the way that PoW superblocks are.
We can still link back to non-PoW blocks as 0-blocks, though (i.e., they're at the lowest $\mu$ level).\footnote{
    Note that, currently, this implies that non-PoW blocks are considered to contribute some work, which they do not in this context (it is not verifiable).
    We will resolve this conflict shortly --- at the end of the section, it will make sense to consider them 0-blocks at the lowest $\mu$ level.
}

Thus, these will not be NIPoPoRs --- this method requires PoW, so, in terms of PoRs, we are only concerned with PoW reflection, rather than all reflection.

\aside{
    You should know, I am only confident about the \emph{principles} of NIPoPoWs, not the specifics.
    So, I claim the following only as an \emph{in principle} argument.
    Further diligence is required.
}

\subsubparagraph{Problem: DAG Compatibility}

\label{sec:nipopowrs-problem-dag-compatibility}

If the longest PoR chain is a DAG, then the interlink will need to be a DAG, too.
Sometimes, two (or more) blocks will be simultaneous, so we will have two (or more) graph tips in those cases.
When that happens, we will always have at least two 0-superblocks (since a 3-superblock is also a 2-superblock, etc).
In fact, at and below the $\mu$ level of the lightest graph tip, all interlink levels will point back to all graph tips.

We are therefore dealing with \mu-superDAGs, not \mu-superchains.

The existing NIPoPoW \texttt{followDown} algorithm should work fine for high level $\mu$-superblocks.
Since simultaneous blocks at such levels will be exceptionally rare, we can expect higher $\mu$-superDAGs to be much more chain-like than the longest PoR chain.

At lower levels (or any level), it doesn't matter which path to the target block we take (if more than one is even available).
The PoR graph has no conflicts and no concept of a ``doublespend'' --- rather, it is a massive graph of interconnected merklized tree structures where vertexes are merkle roots and comprise the leaves of future vertex-roots; thus, edges are merkle branches.
Put another way, there's no sense of \emph{priority} between siblings of the same $\mu$ level.
This is not true for chains using GHOST (or block-DAGs)\footnote{
    GHOST and block-DAGs are the specific focus of \autoref{sec:dos-and-dags}, and we'll discuss this issue properly, then.
} --- in those cases it is possible for an uncle block to be of a higher $\mu$ level than its non-uncle sibling, so this construction doesn't cover those cases.
But, in the case of the longest PoR chain, we are \emph{only} concerned about \emph{whether} a block exists --- it doesn't matter \emph{how} we get there, just that we \emph{can} get there.

Curiously, this change is an alternate solution to the problem of an attacker ``[breaking] chain superquality with non-negligible probability'' addressed in the NIPoPoW paper (Section 7). % S7: An attack

The attack is one that allows an attacker to manipulate the public chain's ``superquality'' (a measure of the frequency of $\mu$-superblocks), such that fewer superblocks become canonical.
In essence, the attacker selectively performs a selfish-mining-like attack whenever a significant $\mu$-superblock is found.
Their goal is to mine an alternate longest chain, such that the superblock becomes stale.
This then allows the attacker to produce, in private, a superior NIPoPoW (compared to that of the public chain) for fewer resources than should be required.

The authors solve this problem via introducing a concept of ``\emph{goodness}'' --- which is basically that proofs must be succinct and ``\emph{good at every level}'' (when this is not possible, provide the whole chain instead).
The authors then show that, when goodness is not violated, the attack is impractical.

In our modified graph-based version, though, there is no such problem: blocks cannot become stale.
Additionally, the \AxiomOfMaximalReflection guarantees that the interlink history will fully span the entire PoR graph.

\subsubparagraph{Problem: Variable Difficulty and Multiple Hashing Algorithms}

There are really two problems here for us to think about.
If we can solve the problem of blocks using different hashing algorithms, then we will need to handle variable difficulty anyway, so let's work on the critical path first (variable difficulty).

\NewDocumentCommand{\tradA}{g}{\IfNoValueTF{#1}{\ensuremath{\mathcal{A}}}{\ensuremath{\mathcal{A}_{#1}}}\xspace}
\NewDocumentCommand{\tradB}{g}{\IfNoValueTF{#1}{\ensuremath{\mathcal{B}}}{\ensuremath{\mathcal{B}_{#1}}}\xspace}

Let's consider the superchains of two very similar traditional chains, \tradA and \tradB, using the same PoW algorithm.
Since these chains use the same hash, we can scale their respective $\mu$ values depending on their relative difficulties.

If the difficulty of \tradB is half that of \tradA, then we can convert $\mu_{\tradA}$ levels into $\mu_{\tradB}$ levels by adding 1.
In this way, all blocks in \tradA are at level $\mu_{\tradA}=0$ which is equivalent to level $\mu_{\tradB}=1$.

We can observe this equivalence via the following thought experiment: what does \tradB's 1-superchain look like if \tradB's block frequency is twice that of \tradA?
First, we should expect that, for a given period, there are twice as many \tradB blocks as there are \tradA blocks.
Since about half of \tradB blocks will have $\mu_{\tradB} \ge 1$, there will be approximately as many \tradB blocks in the $(\mu_{\tradB}=1)$-superchain as in \tradA's $(\mu_{\tradA}=0)$-superchain.

This makes sense: there are twice as many blocks at half the difficulty, so we expect the same hash-rate to be mining on each chain.
If both chains have the same hash-rate, then they should produce the same number of blocks at a given $\mu_{\tradA}$ level.
Since \tradB has the lower difficulty, this is not true for a given $\mu_{\tradB}$ level --- \tradA produces \emph{no} blocks at level $\mu_{\tradB}=0$.

Now, let us modify \tradB's protocol in a strange way.
We'll say that \tradB blocks \emph{must} explicitly include all transactions (in sequence) from all ancestor blocks between the block itself and the prior $(\mu_{\tradB} \ge 1)$-superblock.
We'll also assume that there are suitable optimizations such that this isn't an issue for the \tradB network.
This modification means that no \tradB NIPoPoW ever needs to descend to below $\mu_{\tradB}=1$ again.

For all intents and purposes, \tradA and \tradB produce almost indistinguishable NIPoPoWs (excepting, of course, that they prove blocks in different chains).
Without analysis of the \tradB protocol, and ignoring that all \tradB proofs end at level $\mu_{\tradB}=1$, there is no sign that the \tradB chain has twice as many blocks at half the difficulty.
The proofs are similar sizes, descend the same number of $\mu$ levels, have similar numbers of blocks at each (adjusted) $\mu$ level, etc.
So we might ask the question: how do we know that \tradA doesn't produce blocks at level $\mu_{\tradA}=-1$, similar to \tradB?

The point of this is to demonstrate that $\mu$ levels are relative and convertible between \tradA and \tradB, and there is no appreciable difference based on any $\mu$-offset.
% It is useful to have all $\mu \ge 0$, but this is technically an implementation concern and has no effect in principle.

Therefore, we can express $\mu_{\tradA}$ and $\mu_{\tradB}$ in objective terms by measuring them relative to an arbitrarily low difficulty (e.g., 1).
Let's call the $\mu$ level in terms of a difficulty of 1 the \emph{objective $\mu$} level.\footnote{
    The difficulty is the expected number of hashes to find a solution, so a difficulty of 0 (or below) is impossible.
}
A consequence of this is that duplicate interlink entries (over sequential levels) will be common when there is a large difference between difficulties (i.e., $\mu_{\tradA} \gg \mu_{\tradB}$).
Thus, we should also modify the interlink structure to prepend the $\mu$ level to each group of previous blocks at that level.
This allows us to omit the duplicates, assuming we use an appropriate cryptographic structure (e.g., a merklix tree seems suitable at first glance).

This works because no proof for either \tradA or \tradB will ever need to descend below the minimum objective $\mu$ of that chain's difficulty, and the statistical properties of all higher $\mu$ levels are maintained.
It is no easier for an attacker to generate a malicious NIPoPoW than it would be otherwise.

Further, this is consistent with the observation that, if \tradA's hash-rate doubled, then it would appear as though the minimum $\mu$ level increased by 1 (assuming that $\mu$ levels are not recalibrated according to the current difficulty).

However, this method is only partially consistent with the notion of \emph{goodness} introduced in the NIPoPoW paper --- the statistical distributions of $\mu$-superblocks will only hold until the objective $\mu$ level of a chain's difficulty.
We will ignore this problem as the graph-interlink structure has no need of a goodness measurement.

This resolves the first part of the problem: variable difficulties.

With regards to multiple hashing algorithms, PoR itself has already laid the groundwork for a solution: the conversion of work.
Recall that in \autoref{eq:por-conv-work} we derived \ConvWork: a function for converting R-hashes $\to$ L-hashes.

We can use this to calculate a PoW's equivalent $\mu$ level in terms of another hash.
We can think of converting a block's weight as starting with the chain \cR target, converting that to the difficulty ($\cR_d$ hashes/block), applying $\ConvWork{\cR_d}$, and converting this to the \cL target.
Similarly, we can convert $\mu$ levels using the same process, except that we replace the \emph{actual} target with the \emph{lowest possible satisfiable target} for the block in question.

However, these $\mu$ levels are only comparable after linear scaling, so we need to differentiate them.
From here out, we only need objective $\mu$ values, so let's use $\muType{\cR}$ to refer to the objective $\mu$ of the \cR chain, and $\muType{\cL}$ to refer to that of the \cL chain.
We should note that, for a chain \cC, if we want the $\muType\cC$ level relative to the difficulty, we just need to subtract $\log_2(\cC_d)$ (which is the minimum objective $\muType\cC$ level of any chain \cC block).

Conversion Example: let's start with an \cR chain PoW target of $2^{184}$ --- corresponding to a difficulty of $2^{72}$.
Next, a block is produced with a PoW of $2^{181}$; it has an objective $\muType{\cR}$ of 75.
The minimum target that the block would satisfy is $2^{181}$, which corresponds to a maximum difficulty of $2^{75}$ (\cR-hashes).
Note that $\log_2(\text{max. difficulty}) = \muType{\cR}$.
We then convert this via \ConvWork{2^{75}} to get \cL-hashes.
All that remains is to take and take $\log_2$ to get the converted objective $\muType{\cL}$.

What can we say about \muType\cR's relationship with \muType\cL?
Consider that, in the SRT context, \autoref{eq:por-conversion-const-1} simplifies to $\cL_d \cR_r (\cR_d \cL_r)^{-1}$.
Therefore:
\begin{align}
    2^{\muType\cR} \cdot \cL_d \cR_r (\cR_d \cL_r)^{-1} &= 2^{\muType\cL} \nonumber \\
    2^{\muType\cR} \cdot \cR_r / \cR_d &= 2^{\muType\cL} \cdot \cL_r/\cL_d \nonumber \\
    \log_2(2^{\muType\cR} \cdot \cR_r / \cR_d) &= \log_2(2^{\muType\cL} \cdot \cL_r/\cL_d) \nonumber \\
    \muType\cR - \log_2(\cR_d) + \log_2(\cR_r) &= \muType\cL - \log_2(\cL_d) + \log_2(\cL_r)
    \label{eq:mu-relative-conv} \\
    \muType\cR + \log_2(\cL_d \cR_r) - \log_2(\cL_r \cR_d) &= \muType\cL
    \label{eq:mu-type-conv}
    % \intertext{using non-objective $\mu$ values:}
    % 2^{\muType\cR} \cR_d \cdot \cL_d / \cR_d &= 2^{\muType\cL} \cL_d \\
    % 2^{\muType\cR} &= 2^{\muType\cL}
\end{align}
Note that $\muType\cR - \log_2(\cR_d)$ (\autoref{eq:mu-relative-conv}) is the block's relative $\muType\cR$ level (and similarly for \muType\cL on the right-hand side).

All that remains is for each block in the longest PoR chain to calculate objective $\mu$ values of the same type using \autoref{eq:mu-type-conv}.

Earlier, we determined that objective $\mu$ values of the same type can accommodate variable difficulties.
Thus, we have resolved both parts of the problem.

\subsubparagraph{NIPoPoWRs: Summary}

We have sketched the explanatory framework and construction of a variant of NIPoPoWs that is compatible with the longest PoR chain: NIPoPoWRs.

NIPoPoWs were modified in the following ways:
\begin{enumerate}
    \item Convert (via PoR) each chain's native $\mu$ values into a common type for the interlink structure.
    \item Use objective $\mu$ values to accommodate variable difficulties.
    \item Replace the tree-interlink structure with a graph-interlink structure.
\end{enumerate}

The \AxiomOfAvailability means that the PoR graph does consensus on which blocks exist.
The \AxiomOfMaximalReflection means that the interlink structure spans the entire PoR graph.
Thus, any path to a block is a valid path and we don't need to introduce the notion of \emph{goodness}.

We should also note that this construction does not (yet) work for block-DAGs (including GHOST).
We will continue this construction in \autoref{sec:blockdag-nipopowrs}.

\aside{
    Although we are considering a graph-interlink structure, we should note an obvious optimization.
    First, let's notice that: when introducing multiple back-links to blocks of equal $\mu$ level, those new blocks \emph{must} be a subset of the PoR tips recorded in the header (since there might be other tips that are of a lesser $\mu$ level).
    Thus, we don't actually need to include both/all in the interlink structure, since we always have access to both/all paths via the PoR tips in the header, which is already part of the NIPoPoWR.
}
